# WAR ROOM M1.1 — deployment hardening

Scope: expiry, revocation, dependency review and verification only.

## Capability hardening

Capabilities expire after 14 days. Validation enforces issuance age and maximum signed lifetime, rejecting legacy 90-day tokens. Each private read validates signature and case/run scope, then checks D1 revocation. Missing records, revoked cases and database failures fail closed. Revocation blocks all capabilities for the case, including subsequently minted tokens, without affecting another case.

Migration 0002 adds nullable revoked_at to benchmark_submissions and a trigger preventing removal or alteration of an existing revocation. It is additive and has not been applied to production. Revocation blocks future access, not processing permission or already downloaded copies. No new authentication platform or revocation UI.

An authorized D1 operator can issue a case-scoped update. Replace the placeholder only with a verified case UUID and record who revoked access and why. Revocation is permanent; repeating this statement changes nothing:

    UPDATE benchmark_submissions
    SET revoked_at = strftime('%Y-%m-%dT%H:%M:%fZ','now')
    WHERE case_id = 'REPLACE_WITH_VERIFIED_CASE_UUID' AND revoked_at IS NULL;

## Deployment prerequisites

1. Provision D1 and replace the placeholder binding ID. Apply migrations 0001 and 0002; verify revocation live. No production migration was performed here.
2. Set exact HTTPS BENCHMARK_ORIGIN, high-entropy BENCHMARK_CASE_SECRET (at least 32 characters), Access team hostname and reviewer audience.
3. Protect BOTH /review/_ and /api/benchmark/review/_ with Cloudflare Access for designated reviewers; verify issuer, signature and audience live.
4. Deploy compiled Worker/assets only. Keep Codespaces ports, developer previews and debug services private. Do not expose diagnostic source maps.
5. Set reviewer turnaround within 14 days with a comfortable margin. No refresh endpoint exists. Confirm permanent case revocation and signing-key rotation procedures.
6. Configure a small beta submission limit/rate rule and assign contact/evidence retention and deletion responsibilities. Accept redacted structured summaries only. Redaction checks are limited patterns plus submitter attestations, not comprehensive PII detection.
7. Before inviting practitioners, smoke-test live submission, async draft, Access review, private report, expiry, revocation and isolation.

No Stripe, Resend, Queue, new AI functionality, incumbent search, redesign or deployment. Stop after this gate.
